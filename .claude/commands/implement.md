Реализуй утверждённый план.

Порядок для доменной логики (`service.go`, чистые функции — decay, уровни, стрик, claim):

1. Тест первым. Убедись, что он падает по правильной причине.
2. Минимальный код, делающий его зелёным.
3. Рефактор при зелёных тестах.
4. Для функций со временем — тест внутри `synctest.Test`, время параметром,
   без `time.Sleep`.
5. Для claim и идемпотентности — тест на гонку с `-race` против настоящего Postgres
   (testcontainers), не «должно работать».

Для хендлеров, `repo.go` и wiring TDD не требуется: достаточно, чтобы компилировалось
и проходил один сквозной сценарий.

Правила на всё время работы:

- Меняешь форму запроса/ответа → `docs/openapi.json` в том же диффе. Кодоген ещё
  не подключён (`make gen` сегодня no-op), поэтому типы пиши руками строго по спеке
  и отметь это в PR — как только появится oapi-codegen, они станут генерируемыми.
- Не трогай код вне плана. Заметил проблему рядом — назови её в ответе, не чини молча.
- Уперся в пункт `docs/DECISIONS.md` → «Открытое» — остановись, не выбирай сторону.
- Слоевые правила (`service.go` без HTTP, БД только в `repo.go`) проверяет `depguard`.
  Красный линтер — это архитектурная ошибка, а не придирка: чини причину, а не конфиг.

После реализации — запусти `/verify`. Не объявляй готовность до него.
