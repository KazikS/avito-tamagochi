Составь план. Не пиши код на этом шаге.

1. Прочитай реальный код, а не только описания: `docs/openapi.json` (соответствующий тег),
   существующие `internal/<tag>/*.go`, схему миграций. План, не опирающийся на текущий
   код, — бесполезен.
2. Проверь задачу против `docs/DECISIONS.md`. Упирается в раздел «Открытое» — остановись
   и спроси, дальше не планируй. Раздел «Реконсиляция веток» — не стоп-вопрос, это уже
   известные проблемы, можно чинить по плану.
3. Разбей на шаги по 2–5 минут. Для каждого укажи:
   - конкретные файлы, которые меняются
   - что должно стать зелёным после шага (тест или команда)
4. Первой строкой плана, не примечанием, отметь: трогает ли план `docs/openapi.json`,
   чужой пакет, или таблицы `event_inbox` / `energy_ledger` / `reward_grants`.
5. Назови, что осознанно НЕ делаешь в этой задаче.
6. Если задача трогает незнакомое API библиотеки — сверься с документацией установленной
   версии, не с памятью. Особенно Chakra, мажоры Gin, sqlc.

Выведи план и остановись. Жди подтверждения.
