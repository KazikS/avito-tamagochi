### Запуск проекта

#### Список скриптов

- `npm run dev` - запуск проекта в режиме разработки
- `npm run build` - сборка проекта
- `npm run preview` - превью проекта
- `npm run lint` - запуск линтера
- `npm run lint:ci` - запуск линтера с условием полного отсутствия предупреждений
- `npm run lint:fix` - автоматическое исправление всех ошибок где это возможно
- `npm run format` - визуальное исправление кода с помощью prettier
- `npm run format:check` - проверка ошибок prettier
- `npm run gen:api` - генерация типов и docs/openapi.json
- `npm run chakra` - генерация типов chakra

#### При первой установке

Последовательность выполнения команд при первом запуске проекта:
`npm install` -> `npm run dev` - запуск в режиме разработки

### Линтер и форматирование

**Prettier** отвечает только за форматирование, **ESLint** — только за корректность.
Правила ESLint, конфликтующие с Prettier, отключены через `eslint-config-prettier`
последним элементом конфига. Спора двух инструментов за один и тот же код нет.

ESLint работает в режиме с доступом к типам (`projectService`) — без него
ключевые правила ниже физически не могут сработать.

| Правило                            | Зачем в этом проекте                                                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `no-floating-promises`             | RTK Query возвращает промисы почти из каждого вызова. Потерянный промис глотает ошибку сети молча — экран просто не обновляется, без следа в консоли |
| `no-misused-promises`              | `async`-функция в `onClick` и в `useEffect` — источник гонок при быстрых тапах по кнопкам ухода                                                      |
| `switch-exhaustiveness-check`      | `PetMood` — 6 значений, `ErrorCode` — 14, `RejectReason` — 5. Новое значение в контракте обязано сломать сборку, а не тихо провалиться в `default`   |
| `consistent-type-imports`          | В `tsconfig` включён `verbatimModuleSyntax`: без явного `import type` сборка падает                                                                  |
| `no-restricted-globals: fetch`     | Запрещает сеть в обход `shared/api`, где живут конверт `{ data, meta }`, `Idempotency-Key` и мьютекс на `refresh`                                    |
| `no-restricted-imports: createApi` | `createApi` вызывается ровно один раз. Второй экземпляр — второй кэш, и данные питомца разъезжаются между экранами                                   |
