# Инструменты — что каждый предотвращает

Не список «модного стека». Каждый пункт закрывает конкретный риск, который иначе ловится
на ревью (медленно) или на защите (поздно).

**Порядок доверия:** компилятор/кодоген > CI-гейт > рантайм-валидация > ревью агентом >
проза в `AGENTS.md`. Список старается держаться первых двух уровней.

Статус файла: рекомендованные дефолты. Цена ошибки низкая, разворот дешёвый. Не жди
подтверждения, чтобы начать — но если не согласен, скажи: это дешевле, чем откатывать код.

## Контракт — ошибка компиляции, а не находка ревью

- **oapi-codegen** (`github.com/oapi-codegen/oapi-codegen/v2` — путь сменился с `deepmap/`)
  генерирует Go-интерфейсы и типы из `docs/openapi.json`. Хендлер реализует
  сгенерированный интерфейс: переименовал поле, не тронув спеку — не скомпилируется.
- **kin-openapi** (`github.com/getkin/kin-openapi`) как middleware валидации
  запроса/ответа — второй, независимый чек в рантайме: то, что компилируется, но нарушает
  enum/required/format.
- **`@rtk-query/codegen-openapi`** (официальный, в монорепозитории Redux Toolkit) даёт то
  же самое на фронте: типизированные хуки RTK Query из той же спеки. Без него фронт пишет
  типы руками против контракта, который его не проверяет.
- Не Huma, не Fuego: оба code-first (спека рождается из кода). У нас наоборот.

## Гонка на claim награды — протестирована, а не заявлена

- `go test -race` — обязательный шаг CI, не опция.
- **testcontainers-go** — тест идемпотентности и UNIQUE-constraint'а гоняется против
  настоящего Postgres, не мока. Именно это делает «один грант, тест зелёный» проверяемым.

## SQL — читаемый, без магии ORM

- **sqlc** — пишешь ledger/claim-запросы обычным SQL, получаешь типизированные биндинги.
  Осознанно НЕ gorm/ent: ORM прячет именно тот SQL, который на claim-пути надо читать
  построчно, и облегчает написание кода со спрятанной транзакционной багой.
- **pgx** (`jackc/pgx`) как драйвер, **goose** для миграций — уже используется в
  `feat/auth` (`-- +goose Up/Down`), взяли его, а не golang-migrate, чтобы не переписывать
  готовый файл без причины.

## Время — главный источник багов в этом проекте

**Сначала практика, потом библиотеки.** Единственное, что реально делает проект
тестируемым: время — параметр, а не `time.Now()` внутри. `decay(state, from, to)`, а не
`decay(state)`. Без этого не спасёт никакая библиотека; с этим большая часть ядра
тестируется обычными табличными тестами.

- **`testing/synctest`** (стандартная библиотека, стабилен с Go 1.25) — для того, где
  время параметром не сделать: WS-хартбиты, таймауты реконнекта, ретраи, истечение грантов.
  Тест идёт в «пузыре» с фейковыми часами, время двигается мгновенно, когда все горутины
  заблокированы: тест на 30-секундный таймаут исполняется за микросекунды и не флакает.
  Использовать `synctest.Test`. `-race` не отменяет: synctest делает время
  детерминированным, гонки не ловит.
- **rapid** (`pgregory.net/rapid`) — property-тесты поверх табличных: «энергия не уходит
  в минус», «уровень не убывает при неотрицательном приросте».
- **`go test -fuzz`** (нативный) — две цели, полчаса работы: парсер входящих событий
  `/v1/events` и парсер JSONB-конфига правил.
- **santhosh-tekuri/jsonschema** — валидация JSONB-конфига квестов/наград при записи.

## Архитектура — линтер, а не договорённость

- **depguard** (в golangci-lint) — слоевые правила: `service.go` не импортирует
  `net/http`/Gin, БД только из `repo.go`, `pkg/` не импортирует `internal/**`. Конфиг —
  `.golangci.yaml` в корне.
- **forbidigo** — `time.Now()` вне `pkg/` и `cmd/`.
- **exhaustive** — забытый `case` в switch по статусным enum'ам, когда кто-то добавил
  значение и не обновил все переключатели.
- Остальные явно: `errcheck`, `sqlclosecheck`, `rowserrcheck`, `gosec`, `bodyclose`,
  `errorlint`, `gocritic`, `durationcheck`, `staticcheck`.
- **govulncheck** — уязвимые зависимости, одна команда, та же строка рубрики.

## WebSocket

**coder/websocket** (`github.com/coder/websocket`, продолжение `nhooyr/websocket`), не
gorilla: gorilla требует вручную синхронизировать конкурентные записи в одно соединение
или ловить битые фреймы и паники. coder/websocket делает это внутри. При WS-фанауте через
несколько горутин это целый класс багов, а не риск, который держат в голове под дедлайн.

На фронте состояние из WS вливается в кэш RTK Query через `onCacheEntryAdded` на запросе
питомца. Сделанное иначе даёт сокет, обновляющий отдельный слайс, пока кэш отдаёт
устаревшее состояние — и два разных питомца в интерфейсе.

## Агентный воркфлоу

Разделение, которое стоит держать в голове: **хуки** — детерминированные гарантии (их
исполняет харнесс, не модель); **скиллы** — процедурное знание, подгружаемое по
релевантности; **сабагенты** — параллельные подразговоры со своим контекстом. Правило
в `AGENTS.md` модель выполнит «обычно»; то же правило хуком выполняется всегда.

- `.claude/settings.json` — PreToolUse-гард (force-push, `reset --hard`, `DROP TABLE`),
  PostToolUse-`gofmt`, Stop-хук, не дающий закончить ход с красной сборкой.
- `.claude/commands/{plan,implement,verify,review}.md`.
- `.claude/agents/contract-reviewer.md` — ревью того, что компилятор не ловит.
- `.githooks/pre-push` — гейт для человека; Claude-хуки связывают только агента.
- CI на PR — единственный гейт, который видит всех четверых.

**Про Superpowers** (obra/Jesse Vincent, MIT). Зрелый набор скиллов: brainstorming,
worktrees, writing-plans, TDD, code review. Ставится за минуты. Если ставить — брать
`brainstorming` + `writing-plans` + `test-driven-development`, выключить
`subagent-driven-development`. Ставится на уровень пользователя, решение личное, не
общекомандное.

**Про устаревание документации.** Ошибки вида «агент уверенно пишет API, которого нет
в установленной версии» — самый частый класс в этом проекте (Chakra v3, мажоры Gin,
sqlc). Системное лекарство — docs-MCP: Context7 подтягивает актуальную документацию
конкретной версии в контекст вместо памяти модели. Где библиотека даёт свои официальные
скиллы (Chakra, Redux Toolkit) — брать их, они точнее.

## Что тут для нас, а что для рубрики

Под дедлайном полезно знать, что можно двигать.

| Инструмент | Ловит реальный баг | Даёт балл/доверие жюри |
|---|---|---|
| oapi-codegen, kin-openapi, RTK-кодоген | да, дрейф контракта | да (архитектура) |
| testcontainers + тест на гонку | да, задвоенный грант | **да, это момент демо** |
| depguard / forbidigo (слои) | да, размывание слоёв | да, прямая строка про архитектуру |
| sqlc / pgx | да, читаемый claim-путь | косвенно |
| `testing/synctest` | да, весь time-based слой | косвенно |
| `-race`, `exhaustive`, `gosec`, govulncheck | да | да (линтеры — строка рубрики) |
| Playwright, один сценарий | да, сквозной путь | **да, «основной сценарий работает»** |
| `go test -fuzz` | немного, вход ингеста | да, дёшево и заметно |
| jsonschema на конфиг правил | при 10 правилах — мало | **в основном да**, подпирает «правила как данные» |
| golangci-lint + обоснование | да | да, прямая строка рубрики |

Последние строки — не повод их не делать, а повод не тратить на них полдня.
