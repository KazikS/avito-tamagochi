# internal/rewards — критический путь

Это пакет, где выдаются награды. Ошибка здесь означает задвоенный грант или награду,
которой можно поделиться, — то есть провал главного правила кейса.

## Никогда

- Не выдавай награду вне транзакции.
- Не полагайся на проверку «уже выдано?» в коде без UNIQUE-constraint в БД. Проверка
  в коде — гонка, constraint — гарантия.
- Не храни выданное в Redis. Только Postgres (Redis в проекте сейчас не используется —
  `docs/DECISIONS.md`).
- Не возвращай награду как пересылаемую строку-код там, где по `docs/DECISIONS.md`
  вопрос ещё открыт — остановись и спроси.
- Не читай `time.Now()`. Время приходит параметром.

## Всегда

- `BEGIN` → `SELECT ... FOR UPDATE` по пользователю → проверка eligibility →
  `INSERT INTO reward_grants` → `COMMIT`.
- `UNIQUE (user_id, reward_id)` на `reward_grants` — не опционально.
- `REWARD_NOT_ELIGIBLE` → 409, не 403.
- Любое изменение здесь сопровождается тестом на гонку: N параллельных claim'ов одной
  награды → ровно одна запись в `reward_grants`. Против настоящего Postgres
  (`TEST_DATABASE_URL`, `t.Skip` если пусто), с `-race`, не против мока.
- Диффы этого пакета проходят `/review` с сабагентом `contract-reviewer` перед PR.

## Проверить перед тем, как сказать «готово»

Показать вывод теста на гонку, а не строчку «passed».
