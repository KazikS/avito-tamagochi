# Авито Тамагочи

Ави — питомец, который растёт от заботы (корми, играй, мой, укладывай спать) и
приносит за уровень бонусы на реальные услуги Авито. Go + React.
Хакатон, MVP в работе.

**Задача, которую решаем:** у пользователя Авито нет ежедневного повода
вернуться — на площадку заходят, когда что-то нужно купить или продать. Ави
даёт такой повод: питомец заметно проседает за сутки без захода, забота
начисляет опыт, опыт открывает уровни, а уровни — бонусы на платные услуги
самой площадки (продвижение, доставка). Это гейминфикация «поверх» основного
продукта, а не отдельная игра: награда тратится там, где Авито зарабатывает.

Кратко для жюри — `docs/ONE-PAGER.md` (проблема, идея, MVP, ценность).

## Технологии

| Слой | Что | Почему именно это |
|---|---|---|
| Бэкенд | Go 1.25, Gin | требование кейса по языку; Gin — самый обычный роутер, команда его уже знала |
| БД | PostgreSQL 17, pgx v5 **без ORM** | нужны транзакция с `SELECT ... FOR UPDATE` и `UNIQUE`-констрейнт на выдаче награды — с ORM это пришлось бы обходить, а не использовать |
| Миграции | goose | простые SQL-файлы, накатываются самим процессом на старте (`cmd/main.go`) |
| Реальное время | gorilla/websocket | требование кейса (состояние питомца через WebSocket) |
| Контракт | OpenAPI 3 (`docs/openapi.json`) + кодоген | один источник истины: Go-типы через oapi-codegen, TS-типы через openapi-typescript; расхождение ловит джоб `contract-drift` в CI |
| Фронтенд | React 19 + TypeScript (strict), Vite | требование кейса (React 18+, TS) |
| Состояние/сеть | Redux Toolkit + RTK Query | кэш запросов и вливание WS-событий в тот же кэш — иначе в интерфейсе два разных питомца |
| UI | Chakra UI v3 | готовая дизайн-система, выбрана фронтом в коде |
| Линтеры | golangci-lint v2 (`.golangci.yaml`), ESLint flat + Prettier | требование кейса; правила слоёв держит `depguard`, запрет `time.Now()` в домене — `forbidigo` |
| ИИ в продукте | GigaChat + детерминированный шаблон-фолбэк | сервис в РФ, работает на защите без VPN; фолбэк — чтобы фича не падала на сцене |
| Запуск | Docker Compose (postgres + server + frontend) | требование кейса |

Обоснования, которые не влезли в таблицу, и то, что мы **не** взяли (Redis,
sqlc, testcontainers) — `docs/DECISIONS.md`.

## Запуск

Что должно быть установлено — `docs/SETUP.md`. Проверить одной командой:

```bash
make doctor    # версии Go, docker, golangci-lint, node + что не хватает
make setup     # git-хуки этого клона. Без него pre-push не существует
make up        # поднять стек в docker
```

`make up` поднимает Postgres и приложение. Сам compose-файл лежит не в корне,
а в `backend/deployments/docker-compose.yaml` — дальше по тексту он называется
коротко. Строка подключения для локальных интеграционных тестов — та же, что
в нём:

```bash
export TEST_DATABASE_URL=postgres://tamagochi:tamagochi@localhost:5432/tamagochi?sslmode=disable
```

Пользователя, пароль и базу можно переопределить через `POSTGRES_USER`,
`POSTGRES_PASSWORD`, `POSTGRES_DB` — в compose у них есть значения по умолчанию
для локальной разработки. Миграции лежат в `backend/migrations/`; при старте
процесса они накатываются сами (`cmd/main.go` → `postgres.Migrate`), так что
после `make up` делать ничего не нужно. Отдельная цель `make migrate` нужна
только чтобы накатить их на чужую базу, и ей нужен `DATABASE_URL` в окружении —
своей строки подключения у неё нет.

Фронту не нужно ждать бэкенд: `make mock` поднимает Prism-мок контракта на
`:4010`, который отвечает прямо по `docs/openapi.json` — Docker для этого не
нужен. `make dev` — то же плюс стек в Docker. Мок ещё и проверяет запросы:
тело не по контракту получит 422 со списком неверных полей, а не молчаливые 200.

Для разработки фронта — `npm --prefix frontend install && npm --prefix frontend
run dev` (хот-релоуд), отдельно от `make up`/`make dev`. Vite-прокси
(`frontend/vite.config.ts`) уже смотрит на `localhost:8080` для `/api`,
`/debug` и `/ws` — достаточно, чтобы бэкенд был поднят `make up` или
`go run ./cmd` с `APP_ENV=demo`.

`make up`/`docker-compose.yaml` тоже поднимает фронт (`:3000`), но не для
разработки: это собранный продовый бандл за nginx, без хот-релоуда — см.
«Для защиты» → «Что реально построено».

## Проверка

```bash
make test      # быстрый прогон
make verify    # полный гейт: build + test -race + lint + govulncheck + мутации + хуки
```

`make verify` прогоняет то, что джоб `backend` в CI: сборку, тесты с `-race`,
линтер, `govulncheck`. Сверх CI он гоняет ещё два шага, поэтому идёт дольше,
чем можно ожидать: `make mutation` (намеренно ломает домен семью правками и
проверяет, что тесты на каждую краснеют) и `make hooks-test` (тест guard-хука —
хуки здесь уже дважды приезжали сломанными и молча всё пропускали).
Полного совпадения с CI не жди: версия `golangci-lint`
у тебя своя, а в CI запинена, и наборы правил между выпусками расходятся —
источник истины по линтеру именно CI. Джоб `contract-drift` локально не гоняется:
ему нужно чистое дерево, а `verify` запускают как раз с незакоммиченными правками.

Интеграционные тесты берут строку подключения из `TEST_DATABASE_URL` и
пропускают себя, если переменная пуста:

```bash
TEST_DATABASE_URL=postgres://user:pass@localhost:5432/tamagochi make test
```

## Деплой

Публичного URL нет — это несделанная работа, а не забытая: хостинг команда
поднимает сама, и до защиты стек живёт локально (`make up`). То, что к
деплою готово и проверено:

- `backend/build/package/Dockerfile` и `frontend/build/package/Dockerfile`
  собираются и запускаются как есть — проверено сборкой настоящих образов
  и запуском всех трёх контейнеров (`postgres` + `server` + `frontend`) на
  одной сети: статика отдаётся, REST и WebSocket проксируются через nginx
  на бэкенд (см. историю коммитов и `docs/AI-USAGE.md`), не только `go
  test`/`vite build`.
- `docker-compose.yaml` поднимает весь стек, не только бэкенд (кейс требует
  это дословно).
- Миграции накатываются самим процессом при старте (`cmd/main.go` →
  `postgres.Migrate`), отдельного шага перед первым запуском не требуется.

Что нужно от хостинга — любой, который умеет поднять `docker-compose.yaml`
целиком (или собрать оба `Dockerfile` по отдельности; у каждого контекст
сборки — корень репозитория, не `backend/`/`frontend/`) и дать
бэкенду TCP до Postgres:

| Переменная | Обязательна | Значение |
|---|---|---|
| `DATABASE_URL` | да | `postgres://user:pass@host:5432/db?sslmode=...` |
| `HTTP_ADDR` | нет | по умолчанию `:8080` |
| `APP_ENV` | для публичного показа — да | `demo`: без неё `/pet*` и `/ws` отвечают 401 всем — настоящего входа ещё нет (см. «Для защиты» выше) |
| `DEBUG_TOKEN` | для публичного URL — да | без неё `POST /debug/clock/advance` открыт всем посетителям и может дёргать общее демо-время — см. докстринг `requireDebugToken` в `backend/cmd/demo_clock.go` |
| `GIGACHAT_AUTH_KEY` | нет | Basic-креды GigaChat (не сам access token — `internal/advisor` обменивает их сам). Без неё `aiNote` в сводке дня работает на детерминированном шаблоне, без модели — не 500 и не отсутствующее поле |

С `GIGACHAT_AUTH_KEY` стоит проверить на реальном хостинге, а не поверить нам
на слово: живая проверка дошла до `api.giga.chat` (TLS проходит, корневой
сертификат Минцифры встроен в бинарь), но OAuth-хост
`ngw.devices.sberbank.ru:9443` из сети, где велась разработка, был недоступен
на уровне TLS-хендшейка. Похоже на ограничение той сети, а не на баг кода
(`docs/AI-USAGE.md`), — на обычном хостинге обмен токена может просто
заработать. Если нет, продукт остаётся полностью рабочим: `aiNote` считает
детерминированный шаблон.

После первого деплоя — `make seed` с `DATABASE_URL`, указывающим на
продовую базу, один раз наполняет её демо-данными (идемпотентно, безопасно
повторить).

## Структура проекта

Один Go-модуль на репозиторий, его корень — `backend/`, поэтому все команды с
Go запускаются оттуда (в `Makefile` и в CI это уже сделано).

```
backend/
├── cmd/                  точка входа, сборка роутера (wire.go), демо-личность и демо-часы
│   └── seed/             наполнение демо-данными через настоящий домен, не INSERT'ами
├── internal/
│   ├── api/              типы, сгенерированные из docs/openapi.json — руками не править
│   ├── httpx/            общий конверт ответа { data, meta }
│   ├── config/           справочник экономики: кривая уровней, суточный кап опыта
│   ├── pet/              питомец: распад, уход, опыт, уровни, WebSocket-пуш
│   ├── rewards/          награды как энтайтлмент: каталог, транзакционный grant
│   ├── social/           лидерборд и сводка дня
│   └── advisor/          aiNote: GigaChat + детерминированный шаблон-фолбэк
├── pkg/                  инфраструктура, ниже всех фич: authctx, clock, postgres, wsh, pgtest
├── migrations/           goose, *.sql
├── build/package/        Dockerfile бэкенда
└── deployments/          docker-compose.yaml (postgres + server + frontend)

frontend/src/
├── app/                  store, единственный экран
├── features/             pet, leaderboard, summary, rewards, demo-clock
├── shared/               базовый API-клиент, сгенерированные типы, тема Chakra
└── build/package/        Dockerfile фронта + nginx.conf (статика и прокси на бэкенд)

docs/openapi.json         контракт — ground truth
docs/                     ARCHITECTURE, DECISIONS, SETUP, AI-USAGE, RECONCILIATION, ONE-PAGER
scripts/                  doctor, invariant-check, reconcile-check, mutation-check
```

Внутри фичевого пакета всегда три файла и жёсткое разделение ответственности:
`handler.go` (HTTP, Gin) → `service.go` (домен: чистые функции, время
параметром, ни `net/http`, ни SQL) → `repo.go` (единственное место с SQL).
Это не соглашение на словах — нарушение слоя роняет линтер (`depguard`,
`forbidigo` в `.golangci.yaml`), а не ревью.

Таблица «кто кого может импортировать» и шесть архитектурных инвариантов —
`docs/ARCHITECTURE.md`; какие из них реально закрыты тестом, печатает
`make invariants` по коду, а не по документу.

## Для защиты

### Что реально построено

Один вертикальный срез, целиком на настоящем Postgres, а не на моках:

- `internal/pet` — питомец: лениво считаемый распад показателей, уход
  (`feed`/`play`/`wash`/`sleep`/`wake`), опыт и уровни, идемпотентность и
  суточные лимиты через `pet_action_log`.
- WebSocket-пуш (`GET /ws`) — состояние питомца в реальном времени вслед за
  действием, как того требует кейс.
- `internal/social` — лидерборд (`scope=top`, окно 7 дней) и сводка дня
  (`GET /summary/daily`, `POST /summary/daily/seen`).
- Демо-стенд: `make seed` заполняет базу через настоящий `internal/pet.Service`
  (не `INSERT` в обход домена), `make clock HOURS=N` двигает часы демо вперёд,
  не дожидаясь реального времени — decay, недельное окно лидерборда и сутки
  сводки видят один и тот же сдвиг.
- `internal/rewards` — награды как энтайтлмент, не промокод (решение
  `docs/DECISIONS.md` → 10.08, по прецеденту «Портала призов» Авито):
  каталог из 4 наград (cosmetic+soft), транзакционный grant
  (`BEGIN → SELECT ... FOR UPDATE → eligibility → INSERT → COMMIT`,
  `UNIQUE(user_id, reward_id)`), `claim`/`redeem-click`.
- `frontend/src/features/{pet,leaderboard,summary,rewards,demo-clock}` —
  один экран (RTK Query поверх Chakra v3, без роутера — маршрутизировать
  пока некуда, см. «Реальная авторизация» ниже): карточка питомца с
  действиями и живым WS-обновлением, лидерборд, модалка «Итоги дня»,
  панель наград, пульт демо-часов. Против настоящего бэка, не моков —
  типы из `docs/openapi.json` (`npm run gen:api`), не переписаны руками.
- `docker-compose.yaml` поднимает весь стек, не только бэкенд (кейс требует
  это дословно): `frontend/build/package/Dockerfile` собирает статику,
  nginx проксирует `/api`, `/debug`, `/ws` на бэкенд-сервис.
- `internal/advisor` — `aiNote` в сводке дня, единственная интеграция ИИ в
  сам продукт (кейс требует это отдельно, не только в разработке). Модель
  не считает числа и не придумывает действие: ситуацию (какой показатель
  просел, до какой награды ближе всего, какие действия ухода ещё не
  исчерпаны) считает детерминированный код, GigaChat только выбирает одно
  действие из переданного ей списка и пишет фразу голосом питомца — оба
  поля валидируются перед отдачей клиенту. Любой сбой модели (сеть, таймаут,
  невалидный JSON, действие вне списка) переводит `aiNote` на детерминированный
  шаблон — продукт полностью работоспособен с выключенным ИИ, оба пути
  покрыты тестами (`internal/advisor`).

Как это проверено — не на словах: `make verify` (сборка, `-race`, линтер,
`govulncheck`, мутационное тестирование, гард) зелёный на каждом коммите;
слоевые правила (`depguard`/`forbidigo`) лично проверены намеренной поломкой на
каждом новом пакете; гонка на идемпотентность — 16 горутин × 5 раундов против
настоящего Postgres (и `internal/pet`, и `internal/rewards`); фронт — реальный
прогон в headless-браузере против собранного бэка и `make seed` (создание,
действие, level up, claim награды, модалка сводки), не только `tsc`/`eslint`;
`docker-compose` — реальная сборка обоих образов и запуск всех трёх
контейнеров на одной сети (статика, REST и WebSocket проксируются корректно);
`internal/advisor` — каждый путь отказа модели (невалидный JSON, действие вне
списка, таймаут, пустой ключ, не-200 от GigaChat) воспроизведён тестом против

### Что осознанно не построено — и почему

Ничего из списка ниже не забыто: каждый пункт — явное решение, которое можно
найти в `docs/DECISIONS.md` (раздел «Открытое» — стоп-вопросы команды) или в
докстринге кода, который его принял.

- **Стрик и множитель.** Системы нет — `streak` в лидерборде и `multiplier` в
  сводке дня честно нулевые/единичные, а не выдуманные числа. По той же
  причине каталог наград не выдаёт `tier=premium` (требует вехи 100-дневного
  стрика) — контракт его знает, `internal/rewards.DefaultCatalog` не использует.
- **`scope=league`/`scope=friends` лидерборда.** Контракт их знает, реализован
  только `scope=top` — остальные отвечают понятной 422, а не 500 и не молча
  подменяются на top.
- **Реальная авторизация.** `login`+`password` (`feat/auth`) не смержены; демо
  работает через `APP_ENV=demo` и фиксированного пользователя
  (`backend/cmd/demo_identity.go`) — см. `docs/RECONCILIATION.md`.
- **Публичный деплой.** Пока только `make up` локально/на своей машине —
  `docs/DECISIONS.md` → «не решение, а несделанная работа».
