# Использование ИИ

Кейс требует указать, на каких этапах и как использовались нейросети.

**Это не ежедневный журнал.** Мы пробовали формулировку «ведём с первого дня» и честно
признали, что четыре человека под дедлайн его вести не будут. Поэтому источник — история
git, а этот файл собирается один раз, в день 6, перед защитой.

Что делает историю пригодной для восстановления (соблюдаем по ходу, а не в конце):

- Conventional Commits и осмысленные описания PR.
- Коммиты, сделанные с помощью ИИ, несут `Co-Authored-By` соответствующего инструмента.
- Если ИИ повлиял на решение, а не только на код, — строка «почему» в
  `docs/DECISIONS.md` пишется человеком и своими словами.

Сборка черновика в день 6:

```bash
git log --pretty='%ad %an %s' --date=short --no-merges | sort
git log --grep='Co-Authored-By' --pretty='%ad %an %s' --date=short
```

## В самом продукте

Кейс требует LLM-интеграцию в сам продукт (`aiNote` — персональная фраза от питомца в
сводке дня, `docs/openapi.json` → `DailySummary.aiNote`). **Сделано, с ограничением.**

`GET /summary/daily` заполняет `aiNote` через `internal/advisor`: ситуацию (просевший
показатель, дистанция до ближайшей награды, доступные сегодня действия ухода) считает
детерминированный код, GigaChat выбирает одно действие строго из переданного ей списка
и пишет фразу голосом питомца — оба поля валидируются перед отдачей клиенту. Без
`GIGACHAT_AUTH_KEY` в окружении, или при любом сбое модели (сеть, таймаут, невалидный
JSON, действие вне списка), `aiNote` не пропадает — его считает `TemplateProvider`,
детерминированный шаблон по той же ситуации, без сети. Оба пути — модель и шаблон —
покрыты тестами (`internal/advisor`, `TestSummaryDailyHTTPIncludesAiNoteWhenAdvisorConfigured`).

Ограничение, честно: живой вызов GigaChat end-to-end не подтверждён из этой сессии.
`api.giga.chat` TLS-проверку проходит (после того как в бинарь встроен корневой
сертификат Минцифры — `internal/advisor/certs.go`, без него настоящий сертификат не
верифицируется обычным системным доверием); OAuth-хост `ngw.devices.sberbank.ru:9443`
из сетевой песочницы агента недоступен на уровне TLS-хендшейка, воспроизводимо. Это
похоже на сетевое ограничение окружения разработки, а не на баг реализации — обмен
Authorization key на access token реализован по документации и покрыт тестами против
`httptest.Server`, но без доступного OAuth-хоста ни один тест не может доказать, что
именно живой обмен токеном работает. Формулировка на защите должна отражать это прямо:
слой спроектирован и протестирован под модель, включая известный подводный камень с
сертификатом, но живой прогон через настоящий GigaChat ещё предстоит на машине с
доступом к нему.
