гарантию ни в ревью, ни на защите.

| 06.08 | Случайностные тесты | Дифференциальный тест против наивной модели, seeded `math/rand` | Распад состояния считается «лениво» (в закрытой форме от `LastDecayAppliedAt`), наивная модель — по шагам. ## Предложено — можно оспорить, владельца пока нет

Ни одно ещё не написано ни строчкой. Это кандидаты, а не решения.

- **oapi-codegen** — spec-first кодоген Go из контракта; хендлер реализует
  сгенерированный интерфейс, расхождение со спекой становится ошибкой компиляции.
- **kin-openapi** — middleware валидации запроса/ответа. Второй слой поверх кодогена,
  ловит то, что компилируется, но нарушает enum/required/format. Смысл имеет только
  после oapi-codegen.
- **`@rtk-query/codegen-openapi`** — типизированные хуки RTK Query из той же спеки.
- **coder/websocket** — не gorilla: конкурентная запись в одно соединение и битые
  фреймы обработаны внутри библиотеки. На фронте состояние из WS вливается в кэш
  RTK Query через `onCacheEntryAdded`, иначе в интерфейсе будет два разных питомца.
- **testcontainers-go** — герметичный Postgres в тестах; нужен, только если
  `TEST_DATABASE_URL` окажется неудобным в CI.
- **Playwright** — один сквозной сценарий.

## Открытое — остановись и спроси

**Entitlement наград.** `cosmetic` выдаётся напрямую; `soft`/`premium` всё ещё несут
буквальный `promoCode`, который можно переслать. Разбор предлагал entitlement. Прямо
касается главного правила кейса про анти-абьюз — самое дорогое из открытого.

**Кривая уровней.** 25 уровней / `100×1.25^(L-1)` против 12 почти линейных + сезоны.
Трогает экраны фронта и баланс наград.

**Концепт питомца.** Не выбран.

**Redis.** По умолчанию нет: Postgres тянет лидерборд и фанаут на масштабе хакатона,
а second stateful service под дедлайн — новая инфраструктура и лишний вопрос на защите.
Хочешь Redis — приходи с обоснованием, это не дефолт.

**Chakra UI: v2 или v3.** v3 — не апгрейд, а другая библиотека (другой провайдер, тема
через `createSystem`, переименованные пропсы). Агент по умолчанию пишет v2. Берём v3 —
ставим официальные AI-скиллы Chakra до первого компонента. Решение за фронтом, но оно
должно быть решением, а не открытием на четвёртый день.

## Реконсиляция — чиним в этой ветке, не претензия к авторам

`feat/auth` и `feat/pet-service` вливаются сюда как есть, дальше правится здесь.
Проверено мержем обеих веток: конфликтов ровно два (доккомментарий в `postgres.go`
и `go.mod`/`go.sum`), после правок ниже дерево собирается. Пункт уходит из списка,
когда починен, — это чеклист, а не история.

- [ ] `usecase/pet.go` — у `GetPetState` нет тела функции, ветка не собирается
- [ ] `GetPetInfo` читает `c.Param("id")`, а роут зарегистрирован как `/` без `:id`
- [ ] `pet.POST("/action")` — роут без хендлера, паника при первом запросе
- [ ] `repository/user.go` импортирует `grpc/{codes,status}` ради одного кода ошибки —
      заменить на sentinel; gRPC-сервера в проекте нет
- [ ] пароль пишется в БД открытым текстом, колонка без `NOT NULL` — bcrypt + констрейнт
- [ ] `docs/openapi.json` привести к решению по `login`+`password`
- [ ] `User` лежит в пакете `pet` — не его домен
- [ ] две раскладки свести к целевой; после этого проверить, что `depguard` реально
      краснеет на нарушении (сейчас его правила не матчат ни одного файла)
- [ ] `POSTGRES_PASSWORD=1234` и путь `./pgdata/beers_data` в `docker-compose.yaml`
