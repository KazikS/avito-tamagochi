# Решения

## Реконсиляция веток — не открытый вопрос, а факт (прочитать до мержа auth/pet-service)

Прочитаны реальные файлы `feat/auth`/`feat/pet-service`, обе ветки собраны (`go build
./...`), смержены в скретч-ветке — не только сообщения коммитов. Не путать со следующим
разделом «Открытое»: это конкретные вещи, которые надо поправить до мержа в `main`.

- **`feat/pet-service` не собирается.** `usecase/pet.go:16` — у `GetPetState` нет тела
  функции. `go build ./...` падает с `missing function body`. На этой ветке сейчас нет ни
  одного рабочего запроса.
- **`GetPetInfo` всё равно вернёт 400 на любой запрос.** Хендлер читает `c.Param("id")`,
  роут зарегистрирован как `pet.GET("/")` — без `:id` в пути. Тела функции недостаточно,
  роут тоже нужно поправить.
- **`feat/auth` строит логин/пароль, которого нет в контракте.** `docs/openapi.json`:
  `/auth/register` требует `{nickname, timezone}`, `/auth/login` — только `{nickname}`.
  Пароля нет нигде в спеке. `feat/auth` завёл таблицу `users(login, password)`, модель и
  репозиторий на паролях. Один из двух неправ — решить явно, записать сюда, потом
  продолжать auth.
- **Пароль хранится открытым текстом и не обязателен.** `INSERT INTO users (login,
  password) VALUES ...` без хеширования по пути; колонка `password TEXT` без `NOT NULL` —
  схема прямо разрешает пустой пароль. Чинится независимо от предыдущего пункта.
- **Фантомная зависимость на gRPC.** `feat/auth/backend/internal/repository/user.go`
  импортирует `google.golang.org/grpc/{codes,status}` (top-level `require` в `go.mod`,
  тянет весь grpc/protobuf граф) только чтобы написать
  `status.Error(codes.NotFound, ...)` — в проекте нет ни одного gRPC-сервера. Протекает
  транспортным слоем в repo — то самое нарушение, которое `depguard` должен ловить,
  просто с другим транспортом. Заменить на sentinel-error.
- **Модель питомца конфликтов не создаёт — проверено тестовым мержем.** `feat/auth` и
  `feat/pet-service` унаследовали одинаковую `pet.go` (`stats`/`action`/`ActionLog`) от
  общего предка; `feat/pet-service` только переместил файл в `internal/models/`. Git
  резолвит это чистым rename, без конфликта. Реальные конфликты при мерже — `user.go`
  (`feat/auth` кладёт его в каталог, который `feat/pet-service` переименовал целиком) и
  `go.mod`/`go.sum` (несовместимые transitive-деревья grpc и gin — нужен `go mod tidy`
  после мержа, не ручная правка). Заодно: `User` в `feat/auth` лежит внутри пакета
  `pet` — не его домен.
- **Баланс захардкожен в Go, а не описан ни разу.** `feat/pet-service/internal/models/pet.go`
  зашивает пороги настроения (×1.15/×1.0/×0.85) и XP по действиям (10/12/10/8) константами.
  Меняется только пересборкой, и никто не записал эти числа как решение — см. также
  «Энергия/прогресс» ниже, которая тем самым по факту уже отвечена в коде, но не письменно.
- **Два несовместимых layout уже в работе.** `feat/auth`: плоский `internal/{models,repository}`,
  без слоя service вовсе. `feat/pet-service`: layer-first `internal/http/{handlers,routers}`,
  `internal/{models,repository,usecase}`. Ни один не совпадает с целевым layout в
  `docs/ARCHITECTURE.md`. depguard-правила в `.golangci.yaml` рассчитаны на целевой layout
  и пока не проверяют существующий код — это осознанно, не баг конфига.

## Решено — действуй, не спрашивай

Технически недорого развернуть, продуктовых последствий нет. Не согласен — скажи, это
дешевле, чем откатывать код.

| Что | Решение | Почему (кратко) |
|---|---|---|
| Фреймворк | Gin | Уже в `feat/pet-service`, реализация есть |
| БД | PostgreSQL, без Redis (см. «Открытое») | Транзакции и UNIQUE там, где выдаются награды |
| Кодоген (Go) | oapi-codegen (spec-first) | Контракт уже есть и он ground truth |
| Кодоген (TS) | `@rtk-query/codegen-openapi` | Тот же контракт, тот же эффект на фронте |
| SQL | sqlc + pgx, без ORM | Claim-путь надо читать построчно; ORM его прячет |
| Миграции | **goose** | Уже используется в `feat/auth`; golang-migrate этот синтаксис не парсит |
| WebSocket | coder/websocket | Конкурентная запись в одно соединение безопасна изнутри |
| `REWARD_NOT_ELIGIBLE` | 403 → **409** | Это состояние, а не права доступа |
| Layout (целевой) | `handler → service → repo`, пакет на тег OpenAPI | `docs/ARCHITECTURE.md`. Ветки его ещё не используют — см. раздел выше |
| Общая инфраструктура | `backend/pkg/` (не `internal/platform/`) | Уже импортируется из обеих веток — переименовывать накладно |
| Время в домене | параметром, не `time.Now()` внутри | Иначе decay/стрик нечем тестировать |
| E2E | Playwright, один сценарий | Основной сценарий кейса как исполняемая проверка |
| Мок для фронта | Prism из `openapi.json` | Фронт не ждёт бэкенд; мок не надо поддерживать руками |
| Go | `go 1.25.0`, не 1.26.2 | 1.26.2 ломал golangci-lint (нет билда линтера под неё) |

## Открытое — остановись и спроси

Каждый пункт — реальная развилка, где предпочтения команды должны влиять на ответ, и
дорого разворачивается после того, как поверх лёг код.

**Энергия/прогресс.** Только реальные события Авито, или внутриигровой уход
(покормить/поиграть/помыть) тоже начисляет XP и засчитывает день стрика? Контракт
разрешает второе (`dailyCareXpCap`), `feat/pet-service` это уже закрепил в коде
хардкодом. Разбор команды это оспаривал. Письменного решения нет.

**Награды.** `cosmetic` выдаётся напрямую; `soft`/`premium` всё ещё несут буквальный
`promoCode`. Разбор предлагал entitlement. Прямо касается главного правила кейса про
анти-абьюз — самое дорогое из открытого.

**Кривая уровней.** 25 уровней / `100×1.25^(L-1)` против 12 почти линейных + сезоны.
Трогает экраны фронта и баланс наград.

**Концепт питомца.** Не выбран.

**Redis.** Не в «Решено» намеренно: никто в команде его не обсуждал, добавление — новая
инфраструктура под дедлайн, а не дешёвая доработка. Postgres тянет то же самое на
масштабе хакатона. Хочет кто-то Redis — отдельный разговор с обоснованием, не дефолт.

**Chakra UI: v2 или v3.** v3 — не апгрейд, а другая библиотека: другой провайдер, другая
тема, составные компоненты, переименованные пропсы. Агент по умолчанию пишет v2. Берём
v3 — ставим официальные AI-скиллы Chakra до первого компонента. Решение за фронтом, но
оно должно быть решением, а не открытием на четвёртый день.
