# Решения

## Реконсиляция веток — не открытый вопрос, а факт (прочитать до мержа auth/pet-service)

Прочитаны реальные файлы `feat/auth` и `feat/pet-service`, не только сообщения коммитов.
Не путать со следующим разделом «Открытое»: это не развилки для обсуждения, а конкретные
вещи, которые надо поправить до мержа в `main`.

- **`feat/auth` строит логин/пароль, которого нет в контракте.** `docs/openapi.json`:
  `/auth/register` требует `{nickname, timezone}`, `/auth/login` — только `{nickname}`.
  Пароля нет нигде в спеке. `feat/auth` завёл таблицу `users(login, password)`, модель и
  репозиторий на паролях. Один из двух неправ — решить явно, записать сюда, потом
  продолжать auth.
- **Пароль хранится открытым текстом.** `INSERT INTO users (login, password) VALUES ...`
  без какого-либо хеширования по пути. Чинится независимо от предыдущего пункта.
- **Фантомная зависимость на gRPC.** `feat/auth/backend/internal/repository/user.go`
  импортирует `google.golang.org/grpc/{codes,status}` только чтобы написать
  `status.Error(codes.NotFound, ...)` — в проекте нет ни одного gRPC-сервера. Тащит весь
  grpc/protobuf граф ради одного кода ошибки и протекает транспортным слоем в repo —
  то самое нарушение слоёв, которое `depguard` должен ловить, просто с другим транспортом.
  Заменить на обычный sentinel-error.
- **Роут без хендлера.** `feat/pet-service`: `pet.POST("/action")` зарегистрирован без
  единого хендлера. Компилируется, паникует в Gin при первом реальном запросе.
- **Модель питомца существует в двух местах с разной формой.** `feat/auth`:
  `internal/pet/models/pet.go` (старая форма). `feat/pet-service`: `internal/models/pet.go`
  (добавлены `stats`, `action`, `ActionLog`). При мерже это rename+edit конфликт, не
  fast-forward. Заодно: `User` в `feat/auth` лежит внутри пакета `pet` — не его домен.
- **Баланс захардкожен в Go, а не описан ни разу.** `feat/pet-service/internal/models/pet.go`
  зашивает пороги настроения (×1.15/×1.0/×0.85) и XP по действиям (10/12/10/8) константами.
  Меняется только пересборкой, и никто не записал эти числа как решение — see также
  «Энергия/прогресс» ниже, которая тем самым по факту уже отвечена в коде, но не письменно.
- **Два несовместимых layout уже в работе.** `feat/auth`: плоский `internal/{models,repository}`,
  без слоя service вовсе. `feat/pet-service`: layer-first `internal/http/{handlers,routers}`,
  `internal/{models,repository,usecase}`. Ни один не совпадает с целевым layout ниже
  (`docs/ARCHITECTURE.md`). depguard-правила в `.golangci.yaml` рассчитаны на целевой layout
  и пока не проверяют существующий код — это осознанно, не баг конфига, но и не повод
  тянуть реконсиляцию.

## Решено — действуй, не спрашивай

Технически недорого развернуть, продуктовых последствий нет. Если кто-то не согласен —
сказать дешевле, чем откатывать код.

| Что | Решение | Почему (кратко) |
|---|---|---|
| Фреймворк | Gin | Уже в `feat/pet-service`, реализация есть |
| БД | PostgreSQL, без Redis (см. «Открытое») | Транзакции и UNIQUE там, где выдаются награды |
| Кодоген (Go) | oapi-codegen (spec-first) | Контракт уже есть и он ground truth |
| Кодоген (TS) | `@rtk-query/codegen-openapi` | Тот же контракт, тот же эффект на фронте |
| SQL | sqlc + pgx, без ORM | Claim-путь надо читать построчно; ORM его прячет |
| Миграции | **goose** | Уже используется в `feat/auth` (`-- +goose Up/Down`); golang-migrate требовал бы переписывать готовый файл без причины |
| WebSocket | coder/websocket | Конкурентная запись в одно соединение безопасна изнутри |
| `REWARD_NOT_ELIGIBLE` | 403 → **409** | Это состояние, а не права доступа |
| Layout (целевой) | `handler → service → repo`, пакет на тег OpenAPI | Границы кода = границы контракта. `docs/ARCHITECTURE.md`. Существующие ветки его ещё не используют — см. раздел выше |
| Общая инфраструктура | `backend/pkg/` (не `internal/platform/`) | `pkg/postgres` уже импортируется из `feat/auth` и `feat/pet-service` — переименовывать под ними накладно |
| Время в домене | параметром, не `time.Now()` внутри | Иначе decay/стрик нечем тестировать |
| E2E | Playwright, один сценарий | Основной сценарий кейса как исполняемая проверка |
| Мок для фронта | Prism из `openapi.json` | Фронт не ждёт бэкенд; мок не надо поддерживать руками |
| Go | `go 1.25.0`, не 1.26.2 | 1.26.2 ломал golangci-lint (нет билда линтера под неё) — см. `go.mod` |

## Открытое — остановись и спроси

Каждый пункт имеет реальную развилку, где предпочтения команды должны влиять на ответ,
и дорого разворачивается после того, как поверх лёг код.

**Энергия/прогресс.** Только реальные события Авито, или внутриигровой уход
(покормить/поиграть/помыть) тоже начисляет XP и засчитывает день стрика? Контракт пока
разрешает второе (`dailyCareXpCap`, «2 действия ухода = день»), и `feat/pet-service` это же
закрепил в коде хардкодом. Разбор команды это оспаривал. Письменного решения нет.

**Награды.** `cosmetic` выдаётся напрямую; `soft`/`premium` всё ещё несут буквальный
`promoCode`. Разбор предлагал entitlement. Прямо касается главного правила кейса про
анти-абьюз — самое дорогое из открытого.

**Кривая уровней.** 25 уровней / `100×1.25^(L-1)` против 12 почти линейных + сезоны.
Трогает экраны фронта и баланс наград.

**Концепт питомца.** Не выбран.

**Redis.** Не в «Решено» намеренно: никто в команде его не обсуждал, добавление — новая
инфраструктура (леги на ZSET, pub/sub для WS-фанаута, TTL-счётчики капов) под дедлайн, а не
дешёвая доработка. Postgres тянет то же самое на масштабе хакатона. Если кто-то хочет Redis —
это отдельный разговор с обоснованием, не дефолт.

**Chakra UI: v2 или v3.** v3 — не апгрейд, а другая библиотека: другой провайдер, другая
тема (`createSystem` вместо `extendTheme`), составные компоненты, переименованные пропсы
(`isOpen`→`open`, `colorScheme`→`colorPalette`, `useToast`→`toaster`). Агент по умолчанию
пишет v2. Если берём v3 — ставим официальные AI-скиллы Chakra до первого компонента.
Решение за фронтом, но оно должно быть решением, а не открытием на четвёртый день.
