# Архитектура

Единственное место, где описаны раскладка, слои и инварианты. `AGENTS.md` на них
ссылается и не повторяет. Что чиним после мержа веток — `docs/RECONCILIATION.md`.

`golang-standards/project-layout` не используем: это не стандарт, и Go-репозитории
обычно проще. Начинаем просто, добавляем структуру по боли.

## Раскладка

Целевая. На `feat/auth` и `feat/pet-service` пока две другие — сведение описано
в `docs/RECONCILIATION.md`.

```
backend/
├── cmd/
│   ├── main.go        процесс: слушатель, останов по сигналу
│   └── wire.go        сборка роутера — отдельно, это самый конфликтный файл
├── internal/
│   ├── api/           типы из docs/openapi.json, сгенерированные; руками не править
│   ├── httpx/         конверт { data, meta } — общий для фич способ ответить
│   ├── advisor/       совет для aiNote (DailySummary), не тег контракта — см. ниже
│   ├── config/        ─┐
│   ├── pet/            │ один пакет на тег OpenAPI,
│   ├── tasks/          │ внутри handler.go / service.go / repo.go
│   ├── streak/         │
│   ├── rewards/        │
│   └── social/        ─┘
├── pkg/               общая инфраструктура, ниже всех фич и без знания о контракте
│   ├── authctx/       идентификатор пользователя в context
│   ├── clock/         часы как зависимость
│   ├── postgres/      пока только объявление пакета: пул заведёт тот, кто
│   │                  первым напишет repo.go — до этого пулу нечего открывать
│   └── wsh/           реестр WebSocket-соединений по пользователям
└── migrations/        goose
```

`internal/httpx` лежит в `internal/`, а не в `pkg/`, ровно потому, что знает про
контракт: он импортирует `internal/api`, а `pkg/` этого не может (правило
`platform-layer`). Имя файла в нём не `handler.go` и не `service.go`, поэтому
слоевые правила его не трогают — это не слой фичи.

`internal/advisor` — та же логика, второй пример: не тег контракта (своих
HTTP-маршрутов нет), поэтому не подходит под «пакет на тег OpenAPI» ниже.
Ситуацию для него считает `internal/social/handler.go` — единственное место,
которому нужны сразу `internal/rewards` и `internal/advisor`; `service.go`
обеих фич об этом не знает и остаётся чистым. Файл с HTTP-вызовом к внешней
модели называется `gigachat.go`, не `service.go`, — по той же причине, что и
у httpx: иначе `depguard` (service-layer, запрет на `net/http` в домене)
принял бы легитимный вызов внешнего провайдера за нарушение своего же слоя.

`repo.go` появляется тогда, когда пакету нужна база. У `config` его нет: справочник
— это константы, и репозиторий, который ничего не читает, был бы слоем ради
симметрии.

Пакет на тег OpenAPI: граница кода = граница контракта, и для команды из четырёх
человек пакет заодно зона владения.

## Слои и что кому можно

| Слой | Файл | Можно | Нельзя |
|---|---|---|---|
| Транспорт | `handler.go` | Gin, свой `service.go` | pgx, БД напрямую |
| Домен | `service.go` | чистые функции, свой `repo.go` через интерфейс | `net/http`, Gin, pgx, `time.Now()` |
| Данные | `repo.go` | pgx, SQL | HTTP, доменные решения |
| Платформа | `pkg/*` | стандартная библиотека, драйверы | импорт любого пакета из `internal/` |

Интерфейс для `repo.go` — единственное исключение из правила «не заводи интерфейс
без второй реализации»: вторая реализация здесь всегда есть, это фейк в тесте домена.

Проверяется линтером, не ревью: `depguard` (слоевые правила), `forbidigo` (`time.Now()`
вне `pkg/` и `cmd/`), `exhaustive` (забытый `case`) — всё в `.golangci.yaml`.

Правила проверены: если положить `net/http` в `internal/<tag>/service.go` или
импорт `internal/...` в `pkg/`, линтер краснеет — это прогонялось руками на
временных файлах. Ограничивают ли они что-то прямо сейчас, зависит от того,
есть ли файлы вида `internal/<tag>/{handler,service,repo}.go` — это показывает
`make reconcile`. Проверить сами правила: положи `net/http` в такой `service.go`
и запусти `make lint`.

## Инварианты

1. XP начисляется только вместе с записью в лог действий: idempotency-ключ + проверка
   суточного капа. Уход начисляет XP (решено 06.08), поэтому от накрутки защищает лог
   и кап, а не запрет самого действия.
2. Награда привязана к пользователю; никакой пересылаемой строки-кода.
3. `source` (`gamified|organic`) не теряется на пути `event_inbox` → `energy_ledger`.
4. Выдача награды однократна при конкурентных claim'ах (`UNIQUE(user_id, reward_id)` + транзакция).
5. Время в домене — параметр, не `time.Now()` внутри.
6. Прогресс пользователя не обнуляется миграцией.

Инвариант без теста не существует, что бы тут ни было написано. Сегодня покрыты
тестом пять из шести (`make invariants` — источник истины, не эта страница):
1 — интеграционным тестом против настоящего Postgres (`TEST_DATABASE_URL`);
2 и 4 — там же плюс тестом на гонку с `-race`; 5 — табличными тестами на
`decay(state, from, to)` плюс дифференциальным тестом против наивной пошаговой
модели (ленивый расчёт распада обязан с ней совпасть); 6 — статической
проверкой Up-секции каждой миграции (`backend/migrations/migrations_test.go`):
ни одно SQL-выражение не смеет нести `DROP`/`TRUNCATE`/`UPDATE` рядом с
таблицей, где живёт прогресс пользователя. Только 3 теста не имеет:
`event_inbox`/`energy_ledger` — часть более широкой версии экономики, которую
команда не строит (`docs/DECISIONS.md` → «Открытое»), а не забытый тест на то,
что уже есть.

Тест, доказывающий инвариант N, несёт маркер `// invariant:N` в комментарии
над функцией. `make invariants` (`scripts/invariant-check.sh`) грепает эти
маркеры и печатает, у каких из шести есть тест, а у каких нет — по коду, а не
по этой странице.

⚠️ Раньше здесь было "считает `git ls-files '*_test.go' | wc -l`, ноль значит
инвариантов нет". Формулировка сама была тем самым дефектом, о котором
предупреждает первый абзац этого раздела: число файлов с тестами росло от
любого теста (httpx, wsh, clock — ни один не про инвариант) и в какой-то
момент стало больше нуля, молча читаясь как «инварианты есть». Не повторяй
этот приём для `make invariants`: если появится седьмой инвариант, у него
должен быть свой маркер и свой тест, а не рост общего счётчика тестов.
