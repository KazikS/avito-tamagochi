# Архитектура

Единственное место, где описаны раскладка, слои и инварианты. `AGENTS.md` на них
ссылается и не повторяет. Что чиним после мержа веток — `docs/RECONCILIATION.md`.

`golang-standards/project-layout` не используем: это не стандарт, и Go-репозитории
обычно проще. Начинаем просто, добавляем структуру по боли.

## Раскладка

Целевая. На `feat/auth` и `feat/pet-service` пока две другие — сведение описано
в `docs/RECONCILIATION.md`.

```
backend/
├── cmd/main.go        точка входа: только wiring, никакой логики
├── internal/
│   ├── pet/           ─┐
│   ├── tasks/          │ один пакет на тег OpenAPI,
│   ├── streak/         │ внутри handler.go / service.go / repo.go
│   ├── rewards/        │
│   └── social/        ─┘
├── pkg/               общая инфраструктура: postgres, позже ws — ниже всех фич
└── migrations/        goose
```

Пакет на тег OpenAPI: граница кода = граница контракта, и для команды из четырёх
человек пакет заодно зона владения.

## Слои и что кому можно

| Слой | Файл | Можно | Нельзя |
|---|---|---|---|
| Транспорт | `handler.go` | Gin, свой `service.go` | pgx, БД напрямую |
| Домен | `service.go` | чистые функции, свой `repo.go` через интерфейс | `net/http`, Gin, pgx, `time.Now()` |
| Данные | `repo.go` | pgx, SQL | HTTP, доменные решения |
| Платформа | `pkg/*` | стандартная библиотека, драйверы | импорт любого пакета из `internal/` |

Интерфейс для `repo.go` — единственное исключение из правила «не заводи интерфейс
без второй реализации»: вторая реализация здесь всегда есть, это фейк в тесте домена.

Проверяется линтером, не ревью: `depguard` (слоевые правила), `forbidigo` (`time.Now()`
вне `pkg/` и `cmd/`), `exhaustive` (забытый `case`) — всё в `.golangci.yaml`.

⚠️ Сейчас правила `depguard` не находят ни одного файла: они написаны под целевую
раскладку, а в ветках другая. Пока это так, слои держатся на договорённости, а не на
линтере. Проверить, что правило действительно краснеет, — пункт в `RECONCILIATION.md`.

## Два пути, которые проверяют на ревью

Оставлены здесь потому, что по ним ревьюят: `.claude/commands/review.md`
отсылает к этому файлу за ними.

**Начисление.** `POST /v1/events` → `ingest` → `event_inbox` (idempotency-ключ) →
`energy_ledger` (с `source`) → состояние питомца (XP, уровень) → push по WS.
`source` не должен потеряться ни на одном переходе.

**Выдача награды.** `BEGIN` → `SELECT … FOR UPDATE` по пользователю → проверка
eligibility → `INSERT INTO reward_grants` (есть `UNIQUE(user_id, reward_id)`) →
`COMMIT`. Без транзакции и без UNIQUE конкурентные claim'ы дают два гранта.

## Инварианты

1. XP начисляется только вместе с записью в лог действий: idempotency-ключ + проверка
   суточного капа. Уход начисляет XP (решено 06.08), поэтому от накрутки защищает лог
   и кап, а не запрет самого действия.
2. Награда привязана к пользователю; никакой пересылаемой строки-кода.
3. `source` (`gamified|organic`) не теряется на пути `event_inbox` → `energy_ledger`.
4. Выдача награды однократна при конкурентных claim'ах (`UNIQUE(user_id, reward_id)` + транзакция).
5. Время в домене — параметр, не `time.Now()` внутри.
6. Прогресс пользователя не обнуляется миграцией.

Инвариант без теста не существует, что бы тут ни было написано. Чем проверяется:
1 и 3 — интеграционным тестом против настоящего Postgres (`TEST_DATABASE_URL`);
4 — тестом на гонку с `-race`; 5 — табличными тестами на `decay(state, from, to)` плюс
дифференциальным тестом против наивной пошаговой модели (ленивый расчёт распада обязан
с ней совпасть); там, где время параметром не сделать, — `synctest.Test`.

Ни один из этих тестов ещё не написан: в репозитории нет ни одного `_test.go`.
