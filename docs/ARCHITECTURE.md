# Архитектура

Что где лежит и чем это проверяется — не что-то держим в описании, а то, что ловит
компилятор или CI. Правила для агента — `AGENTS.md`. Что разъехалось между ветками —
`docs/DECISIONS.md` → «Реконсиляция веток». Продуктовое обоснование (Redis, демо-режим,
таймшифт) — там же, не здесь, чтобы не держать одно решение в двух файлах.

`golang-standards/project-layout` — не стандарт (Russ Cox, техлид Go, публично: почти
никто из Go так не раскладывает код). Начинаем просто, добавляем структуру по боли.
Единственное правило, которое реально проверяет компилятор: `internal/` нельзя
импортировать снаружи модуля.

## Раскладка (целевая — см. DECISIONS.md про текущий разъезд веток)

```
backend/
├── cmd/main.go                   точка входа: только wiring, никакой логики
├── internal/
│   ├── pet/                      ─┐
│   ├── tasks/                     │ один пакет на тег OpenAPI
│   ├── streak/                    │ handler.go / service.go / repo.go
│   ├── rewards/                   │
│   └── social/                   ─┘
├── pkg/                          postgres, позже ws, ingest — общий нижний слой
├── migrations/                   goose
└── db/query/                     SQL для sqlc
```

Пакет на тег OpenAPI: граница кода = граница контракта, и для команды из четырёх человек
пакет заодно зона владения.

## Слои и что кому можно

| Слой | Файл | Можно | Нельзя |
|---|---|---|---|
| Транспорт | `handler.go` | Gin, сгенерированные типы, свой `service.go` | БД напрямую, sqlc, pgx |
| Домен | `service.go` | чистые функции, свой `repo.go` через интерфейс | `net/http`, Gin, sqlc, pgx, `time.Now()` |
| Данные | `repo.go` | sqlc, pgx | HTTP, доменные решения |
| Платформа | `pkg/*` | стандартная библиотека, драйверы | импорт любого пакета из `internal/` |

Проверяется линтером, не ревью: `depguard` (слоевые правила), `forbidigo` (`time.Now()`
вне `pkg/`/`cmd/`), `exhaustive` (забытый `case`) — все в `.golangci.yaml`. Правила пока
матчат только целевой layout; на `feat/auth`/`feat/pet-service` они пока ничего не
находят — это ожидаемо до реконсиляции (`docs/DECISIONS.md`), не повод её откладывать.

## Инварианты

1. Прогресс начисляется только по реальному событию Авито *(открытый вопрос — см.
   DECISIONS.md; уже де-факто нарушен хардкодом в `feat/pet-service`)*.
2. Награда привязана к пользователю; никакой пересылаемой строки-кода.
3. `source` (`gamified|organic`) не теряется на пути `event_inbox` → `energy_ledger`.
4. Выдача награды однократна при конкурентных claim'ах (`UNIQUE(user_id, reward_id)` + транзакция).
5. Время в домене — параметр, не `time.Now()` внутри.
6. Прогресс пользователя не обнуляется миграцией.

Каждый инвариант — это тест, не проза: 1 и 3 проверяются интеграционным тестом против
настоящего Postgres, 4 — тестом на гонку с `-race`, 5 — табличными тестами на
`decay(state, from, to)` и, где время параметром не сделать (WS-хартбиты, таймауты),
`synctest.Test`. Если инвариант не тестируется — его нет, независимо от того, что тут написано.
