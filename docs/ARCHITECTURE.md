# Архитектура

Документ для человека и для защиты: что где лежит, почему так, и чем это проверяется.
Правила для агента — в `AGENTS.md`. Что уже разъехалось между ветками — `docs/DECISIONS.md`,
раздел «Реконсиляция веток».

## Почему не «стандартный layout»

`golang-standards/project-layout` — не стандарт. Это репозиторий одного человека, и Russ
Cox, техлид Go, публично написал, что подавляющее большинство Go-пакетов так код не
раскладывает. Официальная рекомендация — начинать просто, добавлять структуру по боли.
Единственное правило, которое реально проверяет компилятор: `internal/` нельзя
импортировать снаружи модуля.

`backend/pkg/` используем не как в том репозитории (свалка «переиспользуемого на
будущее»), а для одной вещи: общей инфраструктуры (`pkg/postgres` сегодня, `pkg/ws`/
`pkg/ingest` — когда понадобятся), которую уже импортируют и `feat/auth`, и
`feat/pet-service`.

## Раскладка (целевая — см. DECISIONS.md про текущий разъезд веток)

```
backend/
├── cmd/main.go                   точка входа: только wiring, никакой логики
├── internal/
│   ├── pet/                      ─┐
│   ├── tasks/                     │ один пакет на тег OpenAPI
│   ├── streak/                    │ handler.go / service.go / repo.go
│   ├── rewards/                   │
│   └── social/                   ─┘
├── pkg/                          postgres, позже ws, ingest — общий нижний слой
├── migrations/                   goose
└── db/query/                     SQL для sqlc
```

`cmd/main.go`, не `cmd/api/main.go` — так фактически лежит на всех трёх ветках, переносить
без причины не стали.

**Почему пакет на тег OpenAPI.** Границы кода совпадают с границами контракта: меняется
тег в спеке — понятно, какой пакет трогать. Для команды из четырёх человек это ещё и
разделение зон владения — два человека реже правят один файл.

## Слои и что кому можно

| Слой | Файл | Можно | Нельзя |
|---|---|---|---|
| Транспорт | `handler.go` | Gin, сгенерированные типы, свой `service.go` | БД напрямую, sqlc, pgx |
| Домен | `service.go` | чистые функции, свой `repo.go` через интерфейс | `net/http`, Gin, sqlc, pgx, `time.Now()` |
| Данные | `repo.go` | sqlc, pgx | HTTP, доменные решения |
| Платформа | `pkg/*` | стандартная библиотека, драйверы | импорт любого пакета из `internal/` |

**Это проверяется, а не просится.** В `.golangci.yaml`: `depguard` (правила
`service-layer`/`handler-layer`/`platform-layer`), `forbidigo` (`time.Now()` вне `pkg/` и
`cmd/`), `exhaustive` (забытый `case` в switch по статусным enum'ам). Нарушение слоя —
красный линтер в CI, а не находка на ревью в последний день. Правила пока матчат только
целевой layout — на `feat/auth`/`feat/pet-service` они пока ничего не находят, потому что
там другая раскладка. Это ожидаемо до реконсиляции, не повод её откладывать.

## Поток данных

Начисление: `POST /v1/events` → `ingest` → `event_inbox` (idempotency key) →
`energy_ledger` (+ `source: gamified|organic`) → состояние питомца (XP, уровень) → WS push.
`source` должен дойти от `event_inbox` до `energy_ledger` без потерь — на этом держится
анти-абьюз и вся аналитика «геймификация против органики».

Выдача награды (критический путь): `BEGIN` → `SELECT ... FOR UPDATE` по пользователю →
проверка eligibility (уровень/стрик/достижение) → `INSERT INTO reward_grants` (`UNIQUE
(user_id, reward_id)`) → `COMMIT`. Гонка здесь — задвоенный грант; транзакция плюс
UNIQUE-constraint делают выдачу однократной, а не рекомендуют её. `REWARD_NOT_ELIGIBLE` →
**409**, не 403 — это состояние, а не права доступа.

Обе схемы выше — иллюстрация, не контракт. Ground truth — код и тесты (интеграционный
тест против настоящего Postgres для `source`, тест на гонку с `-race` для claim'а).
Разошлось с кодом — поправь этот абзац отдельным диффом, не держи в памяти.

## Инварианты

1. Прогресс начисляется только по реальному событию Авито *(открытый вопрос — см.
   DECISIONS.md; уже де-факто нарушен хардкодом в `feat/pet-service`)*.
2. Награда привязана к пользователю; никакой пересылаемой строки-кода.
3. `source` не теряется на пути `event_inbox` → `energy_ledger`.
4. Выдача награды однократна при конкурентных claim'ах.
5. Время в домене — параметр, не `time.Now()` внутри.
6. Прогресс пользователя не обнуляется миграцией.

Инвариант 5 — не стиль, а то, что делает 1–4 тестируемыми: `decay(state, from, to)`
проверяется обычным табличным тестом, `decay(state)` — ничем. Где время параметром не
сделать (WS-хартбиты, таймауты реконнекта, истечение грантов) — тест идёт внутри
`synctest.Test`: фейковые часы, 30-секундный тест исполняется за микросекунды и не флакает.

## Redis — сознательно не используем

См. `docs/DECISIONS.md` → «Открытое». Postgres — единственный источник истины и
единственный стейт-сервис на масштабе хакатона. Появится измеренная (не предполагаемая)
причина — отдельное решение с записью в DECISIONS.md, не дефолт.

## Демо и время

Ядро приложения — время: распад состояния, суточные границы стрика, истечение грантов.
Жюри смотрит десять минут и физически не может увидеть, как проходит время — нужен
служебный эндпоинт сдвига часов (только при `APP_ENV=demo`), почти бесплатный именно
потому, что время в домене параметр. Плюс `make seed`: пользователь в середине стрика,
один у порога уровня, один с готовой к получению наградой, заполненный лидерборд.
